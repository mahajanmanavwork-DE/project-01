Your PySpark Pipeline (The Real Meat)

Step 1: Incremental Extraction
- Airflow DAG triggers daily at 2 AM
- PySpark reads from your API using requests library inside UDF or map partitions
- Also ingest fallback CSV/JSON files dumped by API to /data/raw/YYYY-MM-DD/
- Track watermark: store last_extraction_ts in a Delta table pipeline_metadata.watermark_log

Step 2: Bronze Layer (Raw Landing)
- Dump raw API responses as-is into bronze/orders, bronze/customers, bronze/products, bronze/order_items
- Add _ingestion_ts, _source_file, _batch_id metadata columns
- No transformations, pure append — data lake principle

Step 3: Silver Layer (Cleaned + SCD2 Applied)

Here's where you shine:

- For Orders: Deduplicate on order_id, handle late-arriving updates (order status changes), add is_current flag
- For Customers (SCD Type 2):
  - Compare incoming vs existing on composite key (customer_id)
  - If city, state, phone, or tier changed → expire old record (valid_to = current_date, is_current = False), insert new row (valid_from = current_date, valid_to = NULL, is_current = True)
  - Track scd_hash = MD5 of all tracked columns for efficient change detection
- For Products (SCD Type 2):
  - Same logic on base_price, discount_pct, supplier
  - Price history matters for revenue reconciliation later
- For Order_Items: Join with Silver Orders to validate referential integrity, flag orphan line-items

Step 4: Gold Layer (Business Aggregates)

Build these star-schema fact/dimension tables:

- gold.dim_customer (current snapshot — is_current = True only)
- gold.dim_product (current snapshot)
- gold.dim_date (pre-built date dimension — I'll explain why next)
- gold.fact_daily_sales — aggregated at day grain: total_revenue, total_orders, avg_order_value, top_products, revenue by category
- gold.fact_customer_360 — customer-level aggregates: lifetime_value, total_orders, avg_order_value, preferred_category, churn_risk_flag

Step 5: Additional Features I Demand You Build

Because this separates "meh" from "outstanding":

1. Data Quality Framework (Great Expectations)
   - Between Bronze→Silver: null checks on PKs, duplicate detection, schema validation
   - Between Silver→Gold: referential integrity, aggregate sanity checks (can revenue be negative?)
   - Failed checks → Airflow sends Slack/email alert + pipeline halts

2. Slowly Changing Dimension Reconciliation Report
   - After each run, generate a log of how many SCD2 changes occurred (by table)
   - Store in pipeline_metadata.scd_audit_log for traceability

3. Late-Arriving Data Handling
   - What if an order from 3 days ago arrives now? Your pipeline should identify, backfill, and recompute affected Gold aggregates (partition overwrite on affected dates)

4. Data Lineage & Catalog
   - Use Delta Lake's built-in DESCRIBE HISTORY — write a script that generates a lineage report showing table dependencies
   - Even simpler: maintain a pipeline_metadata.table_catalog with schema, owner, refresh_frequency, SCD_type

5. Incremental vs Full Refresh Intelligence
   - Dimension tables: full snapshot daily (safe)
   - Fact tables: incremental append by created_at
   - Your DAG should accept a --full-refresh flag for disaster recovery

6. FastAPI Serving Layer on Gold
   - GET /sales/daily?date=
   - GET /customers/{id}/360 — returns LTV, tier, order history
   - GET /products/{id}/price-history — full SCD2 timeline visible
